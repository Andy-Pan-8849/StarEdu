# StarEdu 业务模块

[English](README.md) · **[试用指南：环境、搭建、试用数据、账号](TRY-IT.chn.md)**（[English](TRY-IT.md)）

StarEdu 的传统业务系统：一套面向**培训或教育公司的多租户 SaaS 后台**。它管理组织和人员、教学和选课、作业和成绩、成绩单、通知和文档库，也是 [AI 模块](../ai-module/)接入的那个业务系统。它按开源参考实现来做：值得看的不是某一个页面，而是租户隔离、权限、数据范围、审计和测试是怎么从头到尾做完整的。

服务端用 NestJS、Prisma 和 PostgreSQL，浏览器端用 Next.js 15、Tailwind 和 shadcn/ui 风格的组件，登录用 Keycloak。界面以英文为主，中文为第二语言。

## 它能做什么

**平台（运营这套 SaaS 的人用）**
- 开通、编辑、通知、停用和恢复公司（租户）；按公司开关功能。
- 每家公司的登录与安全设置（密码规则、锁定、会话时长、两步验证、可选的 Google 登录），使用情况与配额（账号数、存储），带运行记录的定时任务，平台公告，监控，平台账号和角色。

**公司管理**
- 校区、部门（树）、岗位、账号（邀请、重置链接、临时密码、解锁）、由菜单和按钮组成的角色、数据范围集、菜单和入口分配、字典、参数。
- 操作日志、登录日志、审计日志、在线用户和强制下线。
- 由平台角色模板创建的角色，在模板新增菜单后可以升级（先预览，只补缺的）。

**人员（人事）**
- 一个自然人一条记录，可带员工档案和学员档案；任职有历史（主任职和兼任、调动），离职可立即生效或按计划日期生效。
- 数据分两层：基本信息，和敏感信息加紧急联系人（内置管理员也看不到）。
- CSV 导入导出，可以安全地重复执行。

**教学**
- 学期、带先修关系的课程、**按入学年份分版本的培养方案**、班级（某课程在某学期某校区的一次开课，带任课教师和上课安排）。
- 学生选课和教务代选用同一套规则（名额在行锁下计数、先修、时间冲突、选课窗口）；教务可以填原因确认例外。**批量选课**：按专业、入学年份和校区选人，先预览再执行。
- 退课（退课截止前作废，之后记 W）、课件、班级讨论。

**作业与成绩**
- 作业带评分标准、分组、按校区时间 23:59 截止、迟交扣分表、给单个学生的延期、多文件提交（浏览器直传对象存储）和提交历史版本。
- 按评分标准逐项打分，发布后学生才能看到；成绩册带手工录分、加权总评、发布、结课锁定，结课后的更正要写原因并留下改前改后记录。
- 学期和累计 GPA、公司自己的等级表、重修，以及只显示查看者数据范围内内容的仪表板。

**成绩单与学生申请**
- 带编号的非正式和正式成绩单 PDF，页面带水印、二维码和内容指纹；每份有公开验真页，可作废。
- 学生可以申请成绩复评或作业延期，处理前可撤回；教师和教务批准或驳回并写说明，全程留审计、通知学生。

**沟通与文档**
- 按事件发通知：站内消息、WebSocket 实时推送、按中英文排队发邮件，每个类别可单独开关、邮件带退订链接；公告可发给全公司、一个校区或一个班级。
- 公司文档库：公开、内部、机密三类文件夹，访问级别，会过期的授权，版本，仅查看和带水印的查看方式，机密内容有访问日志。

**AI 集成**
- AI 助手可以运行在*业务模式*：用公司的登录域登录，向本模块询问这个人能看哪些数据行和文件夹，并且只通过按这些范围过滤的只读视图读数据库。

**给开发者**
- 公开试用站：`TRIAL_PROTECT=1` 在演示公司上关掉一小份有风险的操作，每天 `demo:reset` 重建数据（见 `deploy/trial/`）。
- `pnpm gen:module` 一步生成一个普通的租户内资源（带行级安全的表、接口、权限、菜单、页面、测试、泄露扫描登记）。
- 演示模式：一份"正在运转"的演示场景，登录页上的演示账号，一条命令重置（见 [TRY-IT.chn.md](TRY-IT.chn.md)）。

## 它是怎么做的（你会觉得眼熟的行业惯例）

### 多租户：三道互相独立的墙
1. 租户**只来自域名**（`hq.localhost`、`school.example.com`），不来自客户端发来的任何内容。租户不存在：404；已停用：403。
2. 令牌必须由**这个租户自己的 Keycloak 登录域**签发（一个租户一个域）。
3. 每个 Prisma 操作都由扩展自动加上租户条件，写别的租户的行会被拒绝。
4. 数据库再强制一遍：应用用低权限角色连库，**行级安全**只让它看到当前事务设置的那个租户的行；没设置租户就什么也看不到。

外键不受行级安全保护，所以任何接受"别的记录的 id"的接口，都要先检查这个 id 属于当前租户，并登记到**跨租户泄露扫描**里；有路由没登记，测试就失败。

### 身份与权限
- **Keycloak 负责"你是谁"，API 负责"你能做什么"。** 浏览器不持有令牌：网页服务端把令牌放在服务端会话里，用 httpOnly cookie 指向它，调用通过一个后端代理（`/bff/*`）转发，写操作还要带自定义请求头。
- 每个非公开接口都声明一个权限码（`模块:资源:动作`），否则一律拒绝（默认拒绝）。**菜单就是权限**：角色勾选菜单和按钮，上面的权限码就是它的操作权限，并且受限于平台给这家公司开通的功能。
- **数据范围**限制能看到的行：全部、本部门、本部门及以下、仅自己的记录、自己任教的班、或自选一组部门；多个角色取并集；没有范围就没有数据。接口用同一个辅助函数构造过滤条件，写操作也用同一个范围检查目标行。
- 改角色或任职会让该租户的权限版本号加一，缓存的权限在下一个请求就刷新。不能授予自己没有的权限（防提权）。
- 内置角色（租户管理员、学生）不能改；管理员拥有全部操作权限但没有业务数据范围，这是刻意的职责分离。

### 接口与数据
- REST，在边界用 schema 校验（zod）、严格对象，业务拒绝返回明确的错误码，每次变更都写审计。
- 业务规则写在服务层，重要的地方在数据库里再强制一遍（CHECK 约束、触发器、部分唯一索引）。
- Prisma 模型加 `prisma/migrations` 里的迁移，其中行级安全是手写 SQL。种子数据和演示数据加载器都是幂等的（按自然键，可以重复运行）。
- 需要精确的地方用小数运算（成绩），截止时间按校区所在时区。

### 事件与文件
- 事务内**发件箱**：事件和业务变更在同一个事务里写入，由工作进程消费（也可以选配 Kafka 转发）；至少一次投递，带去重、重试和死信。
- 文件由浏览器通过预签名地址直传到兼容 S3 的对象存储；服务端确认对象存在且大小与声明一致；存储键永远以租户开头。

### 安全习惯
- 密码规则、锁定、会话限制和可选的两步验证是按公司管理的登录域设置；保存后密钥不再显示。
- 公开接口（比如成绩单验真）有限速；CSV 导出会防止表格软件把内容当公式；生产环境默认关闭接口文档。
- 演示账号和演示数据只存在于明确标记为演示公司的租户里；演示脚本在 `NODE_ENV=production` 时默认拒绝运行。

### 质量
- **测试跑在真环境上**：PostgreSQL、Redis 和 Keycloak（jest 端到端和集成测试），纯逻辑另有单元测试（vitest）。黄金测试会把样本公司的 198 份提交精确重算一遍。
- **跨租户泄露扫描**用别的租户的 id 把每个读写接口试一遍；结构测试检查每张表都开了行级安全。
- 每次推送，CI 跑 lint、类型检查和全部测试。
- 完成一个功能前，主要流程要在浏览器里走一遍。

### 协作惯例
- 按编号的里程碑（`B1`、`B2` ……）交付：每个里程碑一个分支，改动带自己的测试和文档，CI 通过后用 `--no-ff` 合并并打 `biz-b<N>` 标签。
- 代码、界面文字和文档以英文为主；中文是界面里的第二语言，文档里是 `*.chn.md`。

## 架构与技术

| 部分 | 技术 |
|---|---|
| 接口 | NestJS、TypeScript、Prisma、带行级安全的 PostgreSQL |
| 网页 | Next.js 15（App Router）、Tailwind CSS、next-intl；一个应用里三个入口：学生门户 `/`、管理后台 `/admin`、平台控制台（`platform.*` 域名） |
| 身份 | Keycloak，每个租户一个登录域，另有一个平台登录域 |
| 缓存、会话、锁 | Redis |
| 文件 | 兼容 S3 的对象存储 |
| 邮件 | SMTP（开发用 Mailpit） |
| 事件 | 发件箱表；可选单节点 Kafka（KRaft） |
| 测试 | jest（接口）、vitest（网页、共享包）、supertest |

## 目录结构

| 路径 | 内容 |
|---|---|
| `apps/api` | NestJS 接口（端口 4000）。`GET /healthz` 检查 Postgres 和 Redis。 |
| `apps/web` | Next.js 应用（端口 3001）。 |
| `packages/shared` | 共享代码：权限码、菜单目录、角色模板、租户编码规则、Keycloak 登录域模板、纯业务逻辑（配额、培养方案版本）和模块生成器核心。 |
| `prisma/` | 模型和迁移（`biz` schema）。 |
| `deploy/compose` | Postgres、Redis、对象存储、Keycloak、Mailpit（和可选 Kafka）的 Docker Compose。端口与 AI 模块不同，两边可以同时运行。 |
| `deploy/keycloak` | 密码黑名单，和只用于演示的登录主题。 |
| `scripts/` | 开通租户、种子数据、演示数据加载和重置、模块生成器、本地设密码工具。 |

## 常用命令

```bash
pnpm lint && pnpm typecheck && pnpm test   # 测试需要 Docker 服务（先 make up）
pnpm test:leak                             # 只跑跨租户泄露扫描
pnpm gen:module --name ... --group ... --fields "..." --label "..."   # 生成一个资源脚手架
pnpm demo                                  # 加载演示公司、数据和账号
pnpm demo:reset                            # 从头重建演示数据
```

端口：Postgres 5433、Redis 6380、对象存储 9100/9101、Keycloak 8180、Mailpit 1125（SMTP）和 8125（网页）、接口 4000、网页 3001。

## 它刻意不做什么

不做上传文件的病毒扫描，不做抄袭检测，没有补考、及格/不及格课程、去掉最低分这类成绩规则，没有缴费和学费，没有面向学生的手机应用。管理员永远看不到业务数据。其中一些只是想法，不是承诺。
